## Новая схема фотографий и BASAYA BEACH HOTEL & RESORT — 21.11.2026

**Причина отсутствия фото:** публичный JSON-справочник гостиниц содержит идентификатор, название, страну, курорт и категорию, но **не содержит фотографии**. Ранее клиент применял очень узкий поиск в Wikimedia Commons; для многих коммерческих гостиниц он не давал результата.

**Что изменено:** карточка отеля ищет лицензированные гостиничные фото по нескольким вариантам названия. Если собственных свободно лицензированных фото отеля не найдено, отдельно может загрузить до четырёх CC-фотографий **именно курорта**, с жирной подписью **«Курорт … — НЕ фотография гостиницы»**, указанием автора, лицензии и оригинала. Такой запасной вариант информирует о месте отдыха, но не подменяет реальные номера или территорию чужими снимками.

**Новый официальный источник:** в документации API выгрузки спецпредложений оператор явно описывает поля `hotelPic` и `hotelId`. Сценарий `scripts/oracle_bg_hotel_media_candidates.py` теперь может раз в сутки проверять этот документированный read-only источник и сохранять совпадающие по ID изображения в **приватную** папку Oracle `~/.local/share/jamaica-oracle-catalog/private-hotel-media-candidates.json`. Несовпадающие ID/имена, внешние хосты, небезопасные URL и неправильный JSON отбрасываются. Исходные изображения **не скачиваются и не публикуются автоматически**, потому что доступ к API цен сам по себе не подтверждает лицензию на размещение фотографий в интернет-магазине. Недоступность источника не должна останавливать пяти­минутный импорт туров.

Файл `hotel-media-approved.json` — публичный список разрешённых изображений, первоначально **пустой**. Только если договор/лицензия подтверждает право публикации конкретных файлов, администратор добавляет запись с точным `hotel_id`, названием, страной, `rights_verified=true`, `commercial_publication_allowed=true`, ссылкой на разрешение и фото на разрешённом HTTPS-узле. Карточка проверяет эти поля и не активирует список по одной ссылке `hotelPic`.

**BASAYA BEACH HOTEL & RESORT, ID 102623766108:** в `hotel-enrichment.json` добавлены данные опубликованной карточки: 110 номеров; реновация 2023; категории STANDARD, NEW STANDARD, DELUXE и NEW STANDARD WITH BALCONY; пляж через дорогу, открытый и детский бассейны, завтрак, депозит и время заезда. Источник: https://www.bgoperator.ru/price.shtml?action=shw&code=102623766108&flt=100410000051&page=info&tid=26. **Фотографий самого Basaya с подтверждённым правом коммерческой публикации сейчас не добавлено.** На сайте возможен только явно отделённый фоторяд курорта.

**Развёртывание ежедневного фонового аудита фото на Oracle** требует однократного обновления установленного publisher после GitHub CI:

```bash
cd "$HOME/Загрузки/JAMAICA_WEB_LIVE_BRIDGE_20261120"
git pull --ff-only
bash scripts/upgrade_oracle_catalog_on_server_once.sh
```

После этого Lenovo в регулярных циклах не участвует. Приватный аудит изображений не даёт права автоматически присваивать изображения каталогу и не превращает предварительные цены в подтверждённые продажи.

# JAMAICA — полные карточки гостиниц, фотографии и отзывы

## Что доступно уже сейчас

На сайте `https://rosak8-lgtm.github.io/jamaica-ai-tour-hunter-site/` в результатах поиска реальные варианты туров из прайс-листа находятся **в начале блока**, а нулевой счётчик подтверждённого бронирования больше не закрывает результаты. Каждый найденный вариант содержит кнопку «Подробнее о поездке» и «Подробнее об отеле, фото и отзывы».

В каталоге есть более 11 тыс. отдельных записей гостиниц. Для каждой известной гостиницы теперь работает отдельная ссылка `hotel.html?id=<id>`: название, страна, курорт, категория, найденные в текущих прайс-листах типы номеров, даты и известная рублёвая стоимость пары взрослых. Если в прайс-листе нет гостиницы, фото, номера или цены, это **не выдумывается**: сведения ясно отмечены как отсутствующие.

## Фотографии — только гостиницы, а не случайные пейзажи

Карточка выполняет узкий запрос к публичному API Wikimedia Commons **по названию выбранной гостиницы**, сопоставляет имя с заголовком файла и проверяет `imageinfo.extmetadata.LicenseShortName`. Показываются только фото с поддерживаемой открытой лицензией и с указанием автора, лицензии и ссылки на оригинал. Если таких снимков нет или запрос не выполнен, выводится честная заглушка «Проверенных фотографий именно этого отеля пока нет». Снимок пляжа или другой гостиницы вместо действительного отеля показывать нельзя.

Источник API: https://www.mediawiki.org/wiki/API:Imageinfo
Условия атрибуции: https://attribution.wikimedia.org/attribution-signals/license.html

Задача иметь фотографии **100% гостиниц** не может быть гарантирована только с открытыми источниками. Чтобы заполнять оставшиеся карточки, необходима официальная лицензированная фотобаза или разрешение гостиницы. До подтверждения прав публикация чужих изображений запрещена. Полные описания инфраструктуры (бассейны, питание, Wi-Fi, размер номеров) также требуют проверенных данных конкретной гостиницы. Текст автоматически собирается только из официальных справочных полей, а не из вымышленных удобств.

## Отзывы — серверное хранение и модерация, не GitHub Pages

GitHub Pages — статический хостинг: сам не принимает POST и не хранит пользовательский текст. Для реальных отзывов созданы:

- `backend/hotel_reviews_store.py` — SQLite, отдельный идентификатор отеля, оценки 1–5, тексты до 2500 символов, статус `PENDING/APPROVED/REJECTED`, ограничение частоты и скрытие исходного IP с необратимым HMAC
- `backend/hotel_reviews_api.py` — HTTP API `GET/POST /v1/hotels/<id>/reviews`, только на `127.0.0.1:18778`, CORS только для сайта JAMAICA, POST возвращает `202 PENDING_MODERATION`
- `backend/moderate_hotel_reviews.py` — приватная CLI модерация с подтверждением или отказом; публичного административного интерфейса нет
- `scripts/oracle_install_hotel_reviews.sh` — установка самостоятельного сервера отзывов на Oracle с приватным секретом и SQLite
- `hotel-reviews-config.json` — публичный флаг подключения к проверенному HTTPS API

Посетитель сможет отправить реальный отзыв **после подключения защищённого HTTPS-адреса**. Пока флаг `enabled=false` и адрес API пуст, кнопка отправки на сайте заблокирована; форма не выдаёт ложное «отправлено». Владелец должен подключить HTTPS reverse proxy для локального сервиса Oracle и убедиться, что домен действительно принадлежит ему. Не включайте `enabled=true` без этого.

### Проверка и установка приватного API на Oracle

После получения последней версии кода в серверный GitHub-клон (автономный publisher делает `git fetch`):

```bash
ssh ubuntu@92.5.184.47
cd "$HOME/.local/share/jamaica-oracle-catalog/site"
git pull --ff-only
bash scripts/oracle_install_hotel_reviews.sh
```

Это установит **только приватный** API на `127.0.0.1:18778`. Для приёма отзывов от туристов потребуется публичный домен с валидным TLS-сертификатом, reverse proxy, настройка `hotel-reviews-config.json` и проверка реальной POST/GET с браузера.

### Модерация только на Oracle

```bash
cd "$HOME/.local/share/jamaica-oracle-catalog/site"
set -a; . "$HOME/.config/jamaica/reviews.env"; set +a
python3 -B -m backend.moderate_hotel_reviews \
 --db "$HOME/.local/share/jamaica-hotel-reviews/reviews.sqlite" \
 --directory "$PWD/destination-directory.json" pending
```

Для публикации конкретного отзыва заменить `pending` на `approve --review-id <id>`, для удаления из очереди — на `reject --review-id <id>`. Не публиковать фальшивые отзывы, не раскрывать секреты и паспортные данные. Проверка текста модератором **не доказывает факт проживания**; таким отзывам не присваивается ложный знак «проверенное проживание».

## Автоматические проверки

```bash
python3 -B -m unittest backend.test_hotel_reviews -v
node scripts/test-site.mjs
```

CI также проверяет сайт в Chromium: реальные варианты должны отображаться до блока подтверждённых броней; выбранный тур должен открывать страницу гостиницы; там должны быть справочные сведения, блок фотогалереи и форма отзывов, которая не позволяет отправить текст до подключения публичного HTTPS API.

## Оформление продажи

Карточки отелей и отзывы помогают выбрать тур, но **не заменяют подтверждение цены и мест**. Для настоящей онлайн-продажи по-прежнему требуются личный кабинет туриста, подписанный договор, два повторных расчёта после первого, подтверждение платежа и право создать заявку туроператору. Это отдельные производственные интеграции; при текущих `payments_enabled=false` и `live_booking_enabled=false` сайт не должен принимать деньги или утверждать, что бронь оформлена.
