По журналу Oracle пользователя на 23 ноября, после обновления издателя:
\`PRIVATE_BG_RECEIPTS_STATE=ABSENT\`,
\`JAMAICA_ORACLE_TOUR_COUNT=60000\`,
\`JAMAICA_PUBLIC_VISUALLY_VERIFIED_TOURS=0\`,
\`JAMAICA_PUBLIC_HIDDEN_UNVERIFIED=60000\`,
\`PUBLIC_STRICT_PROJECTION_ENABLED=YES\`.
Это означает **разрыв между старым Telegram BG браузером и публичным website-proof feed**, а не отсутствие предварительных прайс-листов. Старые BG Telegram и PEGAS таймеры не отключать.

## Отдельный сайт-бот (не Telegram)

Пользовательский архив \`JAMAICA_V202_BROWSER_PRICE_RECOVERY_20261123.zip\` служит основой отдельного \`site_bot.py\`. **Собственный systemd timer \`jamaica-website-bg-bot-v1.timer\` каждые 5 минут**. Бот без бюджета, Telegram, WhatsApp и операций покупки. Обходит страны, для которых имеются source-backed записи, приоритеты Таиланд → Китай → Вьетнам плюс другие страны.

Для допуска каждой карточки требуется последовательность:

1. Получить **живую** публичную страницу BG \`/price.shtml?flt=<страна>&flt2=<Иркутск>\`, увидеть точную визуальную метку **«ЛУЧШАЯ ЦЕНА»** у *одной строки маршрута*, а не на баннере/в родительском списке.
2. Playwright \`locator.click()\` на **самой ссылке маршрута** из этого контекста (не выдуманный URL), затем убедиться, что BG не перенаправил браузер на другой \`flt/price/date\`.
3. На открытой странице того же маршрута использовать оригинальный DOM-парсер \`capture_bg_v148.js\` из пользовательского V202 и независимую проверку \`visual_bridge_v148.inspect_snapshot\`: *обе* границы \`li.i_ft\` должны быть настоящими CSS-green, нет stop-sale; сумма отображена как один рублёвый total для двух взрослых.
4. Сверить реальную гостиницу из DOM, название, дату, ночи и полное обозначение комнаты с **одним** preview ID из закрытого source catalog и официальным справочником отелей. Если совпадение не уникально или категория номера не совпадает — **HOLD**, не подставлять иной hotel ID или сумму.
5. Приватный владелец \`ubuntu\` записывает \`private-bg-route-first-receipts.json\` через уже проверенный \`scripts/trusted_bot_receipt_sink.py\`, а в независимый \`private-site-bot-dom-prices.json\` сохраняет рублёвую сумму из **того же браузерного прохода**. Оба файлы \`0600\`. Любое отсутствие подтверждений оставляет **нулевую** выдачу.

Обязательно: у пользовательского V202 **наблюдались ошибки** \`HOLD_BROWSER_UnboundLocalError\` до его патча и после установки ещё не было доказанного успешного рабочего прохода. Новый сайт-бот **не будет автоматически объявлен live**, если не прошла настоящая первая системная проверка; браузерный DOM источник может обновиться или закрыть доступ.

## Цена на JAMAICA

Новый \`scripts/site_bot_price_overlay.py\` загружает приватный ledger и только при полной связи по \`preview_id\`, источнику \`id_price\`, \`browser_session_digest\`, \`flight_checked_at_utc\`, времени до **15 минут** заменяет предварительную сумму API текущим наблюдением браузера. Без этого источник price-list **НИКОГДА** не показывается как актуальная цена прошедшего визуальный фильтр тура.

\`index.html\`, \`preview.html\`, \`hotel.html\` учитывают \`price_source=BG_EXACT_SELECTED_GREEN_BROWSER\` и \`price_observed_at_utc\`. Статус \`bookable=false\`, \`quote_verified=false\` и запрет платежей **не меняются**. Зелёные самолётики и визуальный рублёвый total не гарантируют окончательный ваучер, места или право проведения оплаты.

Обновление каждые 5 минут означает **повторный запуск ограниченного сканера**, а НЕ свежесть всех 60 000 вариантов каждые 5 минут. При реальной смене суммы и успешной новой проверке обновлённая сумма попадает в очередную 5-минутную публикацию. Если конкретный тур не перепроверен в течение 15 минут, его карточка скрывается. Нельзя подменять актуальную сумму вчерашней справочной ценой.

## Запуск с Lenovo

Для отдельного бота сформирован **самостоятельный архив с полными офлайн-исходниками V202 и проверками**. После слияния этого PR и успешного CI:

\`\`\`bash
cd "$HOME/Загрузки"
unzip -oq JAMAICA_SITE_BG_INDEPENDENT_V1_20261123.zip
cd JAMAICA_SITE_BG_INDEPENDENT_V1_20261123
sha256sum -c FILES.sha256
bash run_from_lenovo.sh selftest
bash run_from_lenovo.sh deploy
bash run_from_lenovo.sh status
\`\`\`

Установщик синхронизирует main, вызывает существующее одноразовое обновление **издателя сайта** до модуля визуальной цены, загружает только публично безопасный source code в **отдельный** \`~/.local/opt/jamaica-website-bg-bot-v1\`, проверяет реальные source input и Playwright на Oracle, создаёт только \`jamaica-website-bg-bot-v1.service/timer\`, запускает первый цикл и проверяет, что старый Telegram timer не изменился.

Проверка: \`bash scripts/diagnose_live_visual_link_from_lenovo.sh\` из клона сайта — \`PRIVATE_BG_RECEIPTS_COUNT\`, \`PUBLIC_VISUAL_MATCHES\`, \`PUBLIC_TOTAL_CARD_COUNT\`; затем \`bash run_from_lenovo.sh status\` — независимый таймер. В случае отсутствия проверенного совпадения при работающем сканере \`0\` означает **нет подтверждения**, не «нет туров» или баг интерфейса. Браузерные blocked/timeouts проверить в безопасном journal без паролей и исходных HTML.

**Не устанавливать тестовые доказательства в настоящий feed, не включать бронирование/платежи и не запускать второй процесс с Telegram-токеном.**
