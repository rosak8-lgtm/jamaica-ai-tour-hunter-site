# JAMAICA — два подтверждённых перелёта и метка «ЛУЧШАЯ ЦЕНА»
23 ноября 2026 · политика допуска к реальным продажам

## Фактическое состояние

Выгрузка BG из Иркутска содержит до 60 000 предварительных
отель/дата/номер вариантов по 13 реально найденным странам. Наличие
двухвзрослой справочной цены **не подтверждает** наличие мест в
авиарейсах, гостинице или готовность к оплате.

Официальная BG JSON-инструкция:
https://www.bgoperator.ru/texts/load-xml-prices.html

- Расширение `xml=31` содержит `tourComposition`, где `flight n=0`
  означает вылет туда, `flight n=1` — возвращение. `q[0]` для
  экономкласса: `1..9` или `a` — места по снимку есть; `0` — под
  запрос; `c` — мест нет. **`r` официально документирован** как
  регулярный рейс Аэрофлота с актуальными ценами и данными о местах,
  но этот символ не сообщает однозначного положительного количества
  свободных кресел экономкласса. Поэтому `r` считается
  `REGULAR_NOT_SEAT_VERIFIED`, пока не получены дополнительные
  подтверждения, и НЕ превращается автоматически в зелёный самолётик.
  Это **предварительная оценка**, НЕ блокировка мест.
- Текст «ЛУЧШАЯ ЦЕНА» отображается на отдельных маршрутах официального
  сайта, но в используемой документированной JSON-выгрузке **нет
  достоверного поля**, которое связывает данный интерфейсный маркер с
  конкретным вариантом отеля/комнаты/даты/списка. Нельзя выдавать
  минимальную цену по стране или году за доказательство этой метки.
- Обязательны оба направления: ни один зелёный самолётик в одиночку не
  делает тур допускаемым к продаже.

## Строгая независимая политика продавца

Для текущего авторизованного источника BG серверное значение
`sale_policy=BG_BEST_PRICE_TWO_FLIGHTS` задаёт **сам сервер** и не
принимает это поле от браузера. Для любого перехода к договору и
оплате требуются доверенные, свежие **булевы** подтверждения:

- `flight_out_available=true`, `flight_back_available=true`,
  `flight_pair_evidence_verified=true`: оба направления отдельно
  и соотносятся с выбранным туром.
- `best_price_required=true`, `best_price_verified=true`:
  проверенная на официальном источнике метка именно выбранного
  маршрута/даты/тарифа. В текущей интеграции подтверждение маркера
  ещё отсутствует: нельзя включать его «по умолчанию».
- Заверенная сервером цена с точным составом туристов, гостиница,
  отсутствие stop-sale, три повторные проверки цены (до договора,
  после электронной подписи, после платежа), надёжная подпись и PSP.
  При отсутствии любого условия договор/оплата остаются выключенными.

Для будущего отдельно авторизованного PEGAS адаптера подготовлена
`PEGAS_TWO_FLIGHTS` — зелёные рейсы обязательны, специфическая метка
BG не требуется; это НЕ утверждение, что API PEGAS подключён.

Политика проверяется:
`backend/supplier_sale_policy.py`,
`backend/preview_quote_engine.py`,
`backend/contract_first_order_engine.py`,
`backend/order_engine.py`, а также в трёх клиентских защитных
проверках `index.html`, `tour.html`, `checkout.html`.
Публичный поисковый каталог не исключает непропроверенные варианты,
но показывает явную подпись, что два рейса и маркер ещё не проверены.

## Операционная проверка

```bash
(
set -Eeuo pipefail
cd "$HOME/Загрузки/jamaica-ai-tour-hunter-site"
git pull --ff-only origin main
python3 -B -m unittest -q backend.test_supplier_sale_policy \
  backend.test_flight_availability_evidence \
  backend.test_preview_quote_engine \
  backend.test_contract_first_order_engine \
  backend.test_order_engine
# До пяти независимых официальных прайс-листов Китая
bash scripts/check_green_flights_from_lenovo.sh 'Китай' 5 0

# Вручную проверяем все страны с действительными будущими
# источниковыми карточками JAMAICA (сейчас 13), до 5 списков на страну.
bash scripts/check_green_flights_from_lenovo.sh '--all-observed' 5 1
)
```

Последний скрипт — **только чтение**, печатает по стране счётчики
снимков расширенных прайс-листов. Он не доказывает специальную метку,
не подтверждает бронирование и не запускает платежи.

Продажи остаются выключенными в `checkout-config.json` до подключения
прав продавца, supplier API, правомерной проверки метки на выбранном
прайс-листе, защищённой БД заказов, договорной подписи и PSP.

Параметр страны необязателен. Без него скрипт проверяет страны, которые
указаны в справочнике как направления из Иркутска. С конкретным названием
(например, `Китай` или `Сейшелы`) делает авторизованный запрос строго по
этой стране с `flt2=Иркутск`, даже если устаревший справочник города вылета
не содержит. При отсутствии списка показывает `NO_FUTURE_LIST`.
Вывод `COUNTRY_1_BOTH_GREEN` — число позиций с двумя доступными рейсами
**только в выбранном расширенном прайс-листе**, а не число подтверждённых
к продаже туров: одна и та же гостиница может иметь несколько тарифов.

Значение `BG_BEST_PRICE_MARKER_VERIFIED=NO` остаётся неизменным до
отдельного официального подтверждения точной метки для конкретного
варианта. Финальная цена и бронь по этому диагностическому запросу
не создаются.

## Расширенная проверка по датам, рейсам и всем опубликованным странам

Вывод по стране содержит только безопасные числовые показатели:
`LISTS_ATTEMPTED`, `LISTS_CHECKED`, `LISTS_FAILED`,
`BOTH_GREEN`, `ONE_GREEN`, `NEITHER_GREEN`, `OUT_GREEN`,
`BACK_GREEN`, `OUT_ON_REQUEST`, `BACK_ON_REQUEST`,
`OUT_SOLD_OUT`, `BACK_SOLD_OUT`,
`OUT_REGULAR_UNCONFIRMED`, `BACK_REGULAR_UNCONFIRMED`,
`OUT_UNKNOWN`, `BACK_UNKNOWN`.

Каждый запуск проверяет до пяти разных **настоящих** прайс-листов
страны по разным датам и маршрутам; слот `0`, `1`, `2` позволяет
продолжить ротацию. Отдельный сбой отражается в `PARTIAL_EXTENDED`.
Ноль в `BOTH_GREEN` для одного списка **не доказывает**, что вся
страна не имеет вариантов с двумя доступными рейсами. По разным
спискам могут встретиться одни и те же туры, поэтому сумма счётчиков
не равна количеству разных бронируемых предложений.

Официальные правила продавца поясняют, что отмеченные
«Лучшей ценой» услуги реализуются по специальному промотарифу
с ограничениями на возврат и внесение изменений. Прежде чем
включить продажу такого тура, необходимо отразить эти существенные
условия в настоящем договоре и раскрыть их покупателю с учётом
применимого законодательства:
https://biblioglobus.ru/pages/rules

`BG_BEST_PRICE_MARKER_VERIFIED=NO` остаётся действительным
до получения **самостоятельного точного доказательства** метки для
конкретного маршрута/даты/тарифа. JSON `xml=31` сам по себе
такого подтверждённого поля не предоставляет. Нельзя заменить метку
результатом сортировки списка по минимальной цене.
