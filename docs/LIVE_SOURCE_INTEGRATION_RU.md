- Справочник направлений: 251 корректное название страны, три приоритетных — Таиланд, Китай, Вьетнам; остальные не исключаются.
- Полный полученный публичный справочник гостиниц: 11 046 записей, привязанные страны, курорты и категории. Из 251 страны гостиницы присутствуют в справочнике для 41; для остальных наличие гостиниц по этому источнику не подтверждено.
- Поиск без страны / отеля / даты / длительности показывает варианты справочника с постраничной загрузкой. При конкретизации страны и отеля карточки сужаются. Поиск подтверждённых туров отдельно учитывает дату, длительность, состав и бюджет.
- Карточки отелей открываются на `hotel.html?id=...`; карточки маршрутных прайс-листов на `route.html?id=...`; карточки подтверждённых туров на `tour.html?offer=...` с подробностями гостиницы, затем `checkout.html?offer=...`.

- Синхронизация справочника `destination-directory.json` автоматически запускается через GitHub Actions каждые 6 часов. Данные справочника НЕ являются реальным наличием.

## Почему пока нет действующих цен

Публичная проверка 20.11.2026 API прайс-листов для Таиланда из Иркутска завершилась `HTTP 401`. Это означает, что API требует аутентифицированную сессию. Публикуемые справочники гостиниц не содержат полной текущей стоимости тура и данных о доступности номеров.

Старые наблюдения по отелям не являются подтверждённой доступностью. В `verified-offers.json` сейчас `offers: []`. Покупка и деньги заблокированы, пока не будут готовы источник расчёта, бронирование и эквайринг.

## Выполнить на собственном Lenovo для подключения маршрутных прайс-листов

Учётные данные БГ ранее сохранены в защищённой папке на Oracle; отправлять логин/пароль в GitHub или чат не нужно. Достаточно уже авторизованного GitHub CLI на Lenovo и имеющегося SSH-ключа Oracle.

```bash
(
set -Eeuo pipefail
umask 077
ROOT="$HOME/Загрузки/JAMAICA_WEB_LIVE_BRIDGE_20261120"
if test -d "$ROOT/.git"; then
  git -C "$ROOT" pull --ff-only
else
  test ! -e "$ROOT" || { echo "STOP_DESTINATION_EXISTS"; exit 2; }
  gh repo clone rosak8-lgtm/jamaica-ai-tour-hunter-site "$ROOT"
fi
bash "$ROOT/scripts/sync_price_routes_from_lenovo.sh"
)
```

**Успешный результат:** `JAMAICA_AUTHENTICATED_ROUTE_DISCOVERY_PASS`, `ROUTE_DISCOVERY_PUBLISHED=YES`, `PRIVATE_CREDENTIALS_REMAIN_ON_ORACLE=YES`. Общее количество маршрутов зависит только от фактического ответа API — если ноль, это нельзя трактовать как полное отсутствие туров.

Если появится `JAMAICA_ROUTE_SYNC_HOLD=CREDENTIALS_PATH_NOT_FOUND_USE_OPTION`, значит скрипт не обнаружил известное местоположение вашего закрытого файла учётных данных. Ничего не публикуется, пароли не выводятся. Нужно уточнить только путь на Oracle, без раскрытия содержимого.

**Публичные данные из маршрутов** не содержат цену, внутренний id_price, URL сессии и секреты, потому что строки `action=files` — это ссылки на прайс-листы, не финальная подтверждённая цена для выбранных туристов.

## Следующий этап реальных продаж

1. Для выбранного маршрута загрузить аутентифицированный подробный прайс-лист `action=price` и проверить отель, номер, питание, состав туристов, перелёт, валюту и стоимость.
2. Проверить два зелёных индикатора перелёта и требуемую отметку лучшей цены на той же операторской карточке, не имитируя их. Устаревшие цены не публиковать.
3. Выполнить официальный повторный расчёт через разрешённый агентский API и сформировать свежую подтверждённую котировку.
4. Настроить полномочия создания заявки, последующее бронирование и выдачу документов, заключить условия продажи и возвратов.
5. Разместить коммерческий JAMAICA на серверном хостинге с постоянным HTTPS (GitHub Pages не предназначен для коммерческого магазина) и подключить действующий эквайринг с подтверждением платежа на сервере.

**Не менять** `checkout-config.json` (`live_booking_enabled=false`, `payments_enabled=false`) до готовности реального бронирования и платёжного провайдера.


## Выбранный тур: повторное сопоставление с прайс-листом (20.11.2026)

По запуску с Lenovo опубликованы **3 027 предварительных вариантов** по четырём странам (Индонезия, Россия, Турция, Шри-Ланка). Каталог маршрутов содержит **3 630 строк** по пяти странам. Эти числа относятся к справочным вариантам, **не к проданным или подтверждённым турам**. Thailand API в последнем подробном запросе вернул 0 строк; это не доказывает отсутствия туров на все даты.

Введён защищённый read-only этап сопоставления выбранной карточки с живым источником: `scripts/oracle_bg_selected_quote_probe.py` (выполняется только на Oracle), локальный запуск `scripts/check_selected_tour_from_lenovo.sh`. Сопоставление использует ID `p_...` из опубликованной витрины, дату вылета, гостиницу, ночи и номер. Выводит только количество ценовых вариантов, наличие поля RUR и признаки состава 2 взрослых — **без сумм, внутренних ID, URL и персональных данных**. При отсутствии совпадений выдает HOLD. Прохождение проверки не включает оплату.

Команда после `git pull --ff-only`:

```bash
python3 -B -m unittest backend.test_bg_selected_quote_probe -v
python3 -B -m py_compile scripts/oracle_bg_selected_quote_probe.py
bash -n scripts/check_selected_tour_from_lenovo.sh
bash scripts/check_selected_tour_from_lenovo.sh
```

Для проверки конкретной карточки можно передать её ID: `bash scripts/check_selected_tour_from_lenovo.sh p_...24_символа...`. Если ID не передан, берётся первая карточка текущего файла `tour-previews.json`. Данные авторизации и прайсы не экспортируются.

**До реальных продаж** требуется независимая авторизованная серверная котировка для заявленного количества и возрастов туристов, проверка актуальной доступности гостиницы и обоих сегментов перелёта, разрешённое создание заявки через официальный API, договор продавца, эквайринг и webhook reconciliation. Не меняйте `checkout-config.json` с `false` на `true` до end-to-end испытаний с реальным оператором и платёжным провайдером.


## Прайсовые ориентиры для двух взрослых — версия от 20.11.2026

По последнему проверенному выводу пользователя опубликованы 4 066 предварительных вариантов по Таиланду, Индонезии, России, Турции и Шри-Ланке. Проверка трёх будущих международных вариантов нашла ценовые строки для двух взрослых с рублёвым эквивалентом, но **ни одна заявка не рассчитана и не подтверждена официальным запросом**.

Код `scripts/tour_price_reference.py` разрешает публикацию только **ориентировочной** суммы, когда валюта прайс-листа `cur` известна, `prices/ag` однозначно соответствует двум взрослым, нет стоп-продажи, сумма положительна и представляет рубли по правилам оператора (`amount` при RUB/RUR, иначе `RUR`). Запрещено трактовать эту сумму как финальную котировку, достоверную доступность или гарантию рейсов. Данные, используемые для создания заказа (`prx`, `href*`, `id_price`, `sr`, `c`, персональная информация), не публикуются.

Витрина `index.html` и подробная карточка `preview.html` могут показывать эти ориентиры только в течение **30 минут после публикации** обновлённого файла `tour-previews.json`. Для стоимости на человека делят **полную цену за двух пополам только как справочную среднюю**; это не самостоятельная цена тура на одного. При другом составе путешественников или неясной валюте цена скрывается. В поле бюджета максимальная сумма задаётся **на человека**, поэтому фильтр проверяет сумму пары против двух бюджетов только для 2 взрослых без детей.

Новый экспорт не изменяет `verified-offers.json` и не включает `live_booking_enabled` или `payments_enabled`. Запуск после обновления Lenovo:

```bash
git pull --ff-only
python3 -B -m unittest backend.test_tour_price_reference backend.test_bg_preview_export -v
bash scripts/sync_tour_previews_from_lenovo.sh
git pull --ff-only
python3 -B scripts/local_site_qa.py
```

Перед переходом к реальным продажам необходимы подтверждённые условия агента и разрешение на коммерческое использование прайсов, авторизованный окончательный расчёт на указанных туристов, проверка авиаперевозки и свободных мест, создание заявки только после подтверждения клиента, юридическая оферта и интеграция PSP с независимым серверным подтверждением оплаты. Не отправлять `<confirm/>` в тестовом режиме.
