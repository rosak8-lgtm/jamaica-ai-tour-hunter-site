# JAMAICA: определение города вылета по IP

GitHub Pages не исполняет серверный код. Отдельный Cloudflare Worker получает только приблизительный город через request.cf.city и country. Сервис не обращается к Библио-Глобусу, не пишет IP/координаты в хранилища и не возвращает их браузеру. Сторонний IP lookup API не используется.

## Подключение (Cloudflare Dashboard)
1. Workers & Pages → Create application → Worker. Имя: jamaica-city-geo.
2. Deploy, Edit code. Вставить весь файл edge/departure-city.mjs, Save and deploy.
3. Скопировать фактически выданный HTTPS workers.dev адрес. Открыть его с путём /api/departure-city. Ответ должен иметь schema jamaica.departure-hint.v1, source IP_APPROXIMATE и city (название из списка либо null). Не использовать preview editor для проверки геолокации.
4. После успешного теста изменить departure-geo-config.json в main: enabled=true, endpoint=реальный HTTPS адрес Worker с путём /api/departure-city. Не вставлять IP, API token или ключ.
5. После обновления Pages открыть сайт в новом приватном окне. Оценка города приблизительная; если IP иностранный или неизвестный, сохраняется обычный ручной выбор. Вручную выбранный город запоминается только локально в браузере. Нельзя переписывать выбор клиента после начала работы с формой.
6. Для отключения достаточно enabled=false. Worker CORS допускает текущий GitHub Pages origin. При миграции на другой домен нужно обновить разрешённый origin и тесты.

Это определение города, не поиск туров. Оно не разрешает публиковать туры без текущего совпадения метки ЛУЧШАЯ ЦЕНА и двух зелёных самолётиков и не включает многогородской поиск. Не отключайте действующий поисковый бот.
