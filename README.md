# JAMAICA — поиск путешествий и подготовка онлайн-бронирования

Сайт JAMAICA для поиска вариантов путешествий из Иркутска по нескольким странам. Репозиторий содержит клиентскую витрину, справочник гостиниц, реальные **справочные** варианты дат/номеров из авторизованных прайс-листов, тесты и закрытые по умолчанию механизмы оформления.

## Текущее состояние (20 ноября 2026)

Последний успешный импорт на Oracle: **4 081 предварительный вариант, из них 3 669 с ориентировочной суммой за двух взрослых** по Таиланду, Индонезии, России, Турции и Шри-Ланке, 3 630 маршрутных записей, 11 046 гостиниц в справочнике. После обновления источника цифры меняются. **Ни один предварительный вариант не равен подтвержденному бронированию.**

Сайт показывает другие страны в той же выдаче, поддерживает уточнение страны, дат, отеля и продолжительности, ведёт на подробную карточку выбранной поездки. Отсутствие известной цены не должно полностью скрывать варианты: бюджет для таких карточек требует проверки. Ориентир в рублях для пары взрослых отображается только когда прайс подтверждает валюту и состав: первые 30 минут как свежая справочная сумма, затем с предупреждением об устаревании и отметкой времени — максимум до 24 часов после импорта. Это не финальная цена, а покупка требует новой серверной котировки.

Платёжная и броневая функциональность **не включена**: `checkout-config.json` содержит `live_booking_enabled=false` и `payments_enabled=false`. Справочник 251 страны не означает, что из Иркутска на каждую есть туры. Названия поставщиков не используются в рекламном интерфейсе, но юридически обязательные сведения о продавце и туроператоре должны быть доступны при заключении договора.


## Новый утверждённый порядок продаж: договор → оплата → бронь

**Требование владельца от 20.11.2026:** цена и доступность проверяются три раза: перед договором, после проверенной подписи перед оплатой, после поступления денег перед заявкой. Гостиница может иметь статус «в наличии» или «под запрос» с явным согласием. Только после оплаты и третьей проверки можно создавать заявку в агентском ЛК. При подтверждении туроператором владелец получает отдельное уведомление.

Серверные компоненты с тестовыми адаптерами: `backend/preview_quote_engine.py` (из публичного варианта в приватную котировку), `backend/contract_first_order_engine.py` (подпись → платёж → третья проверка → бронь), `backend/sqlite_order_repository.py` (атомарные статусы и очередь), `backend/send_booking_notifications.py` (уведомления с приватным токеном). Клиентские страницы: `preview.html` → `quote.html` → `checkout.html` → `account.html`.

**Важно:** это реализованная и тестируемая логика с интерфейсами внешних сервисов, **не действующая касса**. Настройки подписи, авторизации, оплаты и реальной брони остаются `false`. Нельзя просто включить флаги без юридического договора, PSP, подтверждённого API агента, подписанной интеграции ЭП и безопасного backend-сервера.

[Подробная последовательность и контракты API](docs/CONTRACT_FIRST_SALES_RU.md).

## Расширенный каталог и безопасность личных кабинетов

По последнему запуску Lenovo (20.11.2026) опубликовано 4 081 предварительное предложение по 5 странам, из них 3 669 с ориентиром в рублях на **двух взрослых**. Новый экспорт проверяет до **13 направлений**, до **трёх различных дат прайс-листов** на направление, с безопасным ограничением **8 000 записей**. Это максимум импорта, а не обещанное число доступных туров: фактическое количество определяется текущим API.

**Исправление состава туристов:** выбранные в поиске взрослые и дети теперь передаются в выбранную карточку и на страницу официального расчёта. Стоимость «2 взрослых» не применяется к одиночным туристам или семьям. Пока доверенная котировка реализована только для двух взрослых без детей, прочие составы блокируются с явным сообщением, а не получают фиктивную цену.

**Защита личного кабинета:** серверные котировки привязаны к buyer_id, который получает приватный сервер после проверки сессии. Нельзя создать договор по чужой котировке. SQLite предлагает отдельные методы get_offer_for_buyer и get_order_for_buyer, но публичный HTTP API авторизации пока не размещён.

**Первый официальный расчёт без создания заявки:** модуль backend/bg_read_only_price_client.py умеет формировать и отправлять **только запрос цены** через официальный HTTPS zayavkaapi, когда запущен на частном сервере с разрешёнными агентскими доступами и данными туристов. Он запрещает <confirm/>, перенаправления и посторонние хосты. **В Oracle боевые вызовы не выполнялись**, поскольку права на API создания заявок, безопасный сбор паспортных данных и авторизованные сессии покупателей пока не подтверждены. Указанная цена сама по себе не доказывает наличие перелётов и мест.

Подробности протокола: https://www.bgoperator.ru/texts/api/tour-api.html. Для электронного оформления могут потребоваться личные данные пассажиров и заказчика; их нельзя публиковать в GitHub, передавать в URL, сохранять в браузерном localStorage или записывать в открытые логи.

**Готовая для проверки модель ≠ действующий магазин.** Боевая продажа зависит от проверки доступности рейсов и квот, юридического продавца и договора, доказуемой электронной подписи, реального PSP, подписанных серверных webhook, авторизованной отправки заявки и её независимого подтверждения туроператором. Все платёжные и броневые переключатели остаются выключенными.

## Точность рублёвой цены, два зелёных самолётика и частота обновления (20.11.2026)

Последний запуск Lenovo опубликовал **6 180** комбинаций отель/номер/дата для пяти стран с вылетом из Иркутска; **5 383** имеют официальную цену в RUB по прайс-листу на пару взрослых. Такая цифра является **ценой на момент выгрузки**, а не вычисленной приблизительной суммой. Она не фиксирует цену до оплаты и не доказывает наличие свободных мест на обоих рейсах после обновления.

В документации Библио-Глобуса (`https://export.bgoperator.ru/`) поле `tourComposition` (`xml=31`) описывает рейсы с направлением `n=0` (туда), `n=1` (обратно) и индикатором `q`: первый символ — места в экономклассе; `1..9`, `a`, `r` означают наличие на момент ответа, `0` требует запроса, `c` — нет мест. Текст `flights` в HTML без проверяемой структуры не даёт права объявлять два самолётика зелёными. Добавлены `scripts/flight_availability_evidence.py`, тесты и **безопасный агрегированный аудит** с Oracle через `bash scripts/check_green_flights_from_lenovo.sh`. Реальный результат аудита нужен до отображения зелёных значков на сайте. Наличие зелёных в момент выгрузки не отменяет три проверки до/после оплаты.

В справочнике 251 страна, но туры из Иркутска могут быть опубликованы только по направлениям, для которых официальная выгрузка содержит соответствующий город отправления и будущие прайс-листы. В текущем наборе 12 подходящих каталожных стран, по пяти есть реальные строки. Импортёр теперь перебирает **все** страны справочника, удовлетворяющие этим критериям, без искусственного обрыва на первых 13; прочие страны остаются доступными для справочного поиска, но не выдаются за реальные доступные туры.

**Ранее:** импорт каталога выполнялся вручную из Lenovo командой синхронизации, а страница загружала `tour-previews.json` только при открытии; таймера автоматической публикации не было в этом репозитории. **После изменений:** открытая страница перечитывает каталог каждые **5 минут** и после возвращения на вкладку. Источник также опрашивает Oracle каждые **5 минут** — после однократного развёртывания серверного таймера `jamaica-oracle-catalog-5min.timer`. Активный старый таймер `jamaica-tour-catalog-refresh.timer` на Lenovo отключается автоматически только после успешного первого запуска на сервере. При выключенном Lenovo сервер продолжает импорт.

**Важно:** таймер обновляет только каталог. Живой запрос окончательной цены и проверку гостиницы/рейсов перед договором, перед оплатой и после оплаты будут выполнять приватные API-адаптеры после подключения и разрешения. Платёж и бронь до тех пор заблокированы.
